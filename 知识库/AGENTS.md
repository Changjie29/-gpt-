# 知识库新增和维护指引

适用于本目录及子目录。后续新增资料沿用同一流程，先读[整理规范](条目整理规范.md)和[模板](模板/新资料模板.md)。

1. 原件、来源记录、知识卡、检索索引分别维护；已有用户原件不覆盖。每份资料核对发布方、完整机型、手册编号、版本、市场/排放及配置。上传日期和PDF生成日期不是出版日期。
2. 新外部资料默认保存原链接、取得时的哈希和自行概述；适合归档全文的原件再按来源许可保存。未取得正文的候选保留在采集记录和待补清单，不伪装成维修知识。
3. 人读知识卡必须注明来源、适用范围及核验状态；每条用`## 条目编号｜标题`，写清事实、条件、疑点和证据页。JSONL与Markdown使用相同编号/标题，不生成第二份事实正文。
4. 扫描页及表格必须目视核对。分别记录PDF物理页和实际印刷页；目录有误时采用正文页脚。只核对选页不能声称全书审校。
5. 型号、排放、版本和原件冲突保留待核实。事实和整理边界分开，不跨机型补造油品、容量、压力、扭矩、接线、故障码或操作参数；故障表原因不是确诊。
6. 更新`sources.json`、`entries.jsonl`、品牌目录和采集记录。事实、安全、系统和资料信息使用规范中的`entry_type`；索引/核验/背景/缺口不当作操作依据。
7. 精确`models`只能填证据支持的型号/别名；`emission_stage`只有原件明确时才填。单个条目的条件不扩展成全书条件。
8. 来源记录模式中`sha256/bytes`属于本地记录文件，`manual_sha256/manual_bytes/manual_pdf_pages`属于下载PDF，必须分开。保留原始网址及版本，不用本地记录哈希冒充原件哈希。
9. 完成后运行`python3 知识库/工具/校验索引.py`、`npm test`和`npm run build:server`。新外链PDF应在清理临时原件前用`--external-pdf 来源编号=/临时原件路径`核验。重新加载服务并检查健康指标和对应机型实际问答；不以索引计数代替功能验证。
10. 按用户授权将完成的数据及必要检索代码保存到GitHub。只暂存任务相关文件；不提交密钥、临时抓取目录或生成产物。更新数量与检查结果，区分GitHub保存、本地验证和网站部署。
11. 公开资料搜索不限于现有品牌或固定网站，优先高质量厂家与可信经销商说明书。可用低并发爬虫发现附件并去重；先检查页面实际内容和搜索相关性，HTTP200、产品标题或下载链接不能自动成为知识事实。取得原文后仍按上述规则核对，宁缺毋滥。
