# 知识库维护说明

本目录保存维护说明，不进入检索索引。可检索资料放在同级分类目录内，例如 `01_通用原理/`。

## 资料格式

- 使用 UTF-8 编码的 `.md` 文件。
- 文件开头说明资料名称、来源、适用机型或通用资料性质。
- 用二级标题 `##` 划分独立故障或主题。每个片段应包含可独立理解的现象、排查依据和适用范围。
- 保留可核对的来源及其版本；只有确认来源后才收录具体参数。
- 原始 PDF、Word、Excel、TXT 或图片需先人工整理成 Markdown，当前脚本不会解析这些文件。

## 扩展

未来如需直接接入 PDF、Word、Excel 或 TXT，在 `server/knowledge/loader.ts` 中新增对应解析器，统一输出现有知识片段结构；RAG 检索与问答接口保持不变。

## 更新步骤

1. 新增或修订分类目录中的 Markdown 原文。
2. 在项目根目录执行 `pnpm knowledge:sync`。
3. 检查 `lib/knowledge.json` 的差异，并到知识页检查标题、来源和检索结果。
4. 将原文与生成索引一起提交到 GitHub。
5. 构建并发布网站后，新资料才会在在线站点使用。

现有 `通用故障诊断.md` 是示例资料，不构成特定品牌、型号的维修标准。资料不充分时，诊断应提示「当前知识库资料不足」。
